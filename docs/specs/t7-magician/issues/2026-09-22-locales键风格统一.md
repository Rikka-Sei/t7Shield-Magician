# locales 键风格统一 — Issue

**状态:** open
**发现日期:** 2026-09-22
**来源:** 双审计（UI/Rust 组织审计 UR15）
**关联章节:** §6（国际化）
**关联决策 ID:** D28

## 1. 现象

两份 locale 资源（zh-CN.yml / en.yml）存在两种顶级命名空间风格混排：

- 功能键用小写点号风格（`nav.` / `action.` / `environment.` / `dashboard.` …）
- 11 个呈现码键以 PascalCase 顶级命名空间出现（`Busy:` / `PasswordRejected:` / `TransportUnavailable:` …）

呈现码键被 `presentation.rs` 的 `MESSAGES` 常量表以字符串引用（`"Busy.reason"` 等），键存在性横跨 `presentation.rs` / 两份 locale 三个文件无编译期校验（测试只覆盖部分键集）。约 40 个顶级键的扁平结构下新增文案的归属全凭记忆。

## 2. 证据链

| 证据 | 位置 |
|---|---|
| PascalCase 呈现码键区 | `crates/magi-app/locales/zh-CN.yml:112-149`（D32 后含 PermissionDenied 共 11 个） |
| MESSAGES 常量表字符串引用 | `crates/magi-app/src/presentation.rs:57-105` |
| 键集一致性测试（部分覆盖） | `crates/magi-app/src/presentation.rs` `test_locale_key_sets_are_equal` |

## 3. 影响

- 同一文件两种风格，新增键的归属判断成本高；
- 键存在性无单一事实源，三个文件间漂移只能在运行期发现。

## 4. 拟议方向

- 呈现码键统一收进 `error.`（或 `presentation.`）小写子树：`error.busy.reason` / `error.busy.advice` …；
- 同步改 `presentation.rs` 的 `CODE_*` 常量与 `MESSAGES` 表的键名字符串；
- 两份 locale 各 ~11 个顶级命名空间合并为一个子树；
- 删除死键（`issue:` 已在 T8 删净，无遗留）。

## 5. 代价与风险

- 机械改动（~33 个键名 × 两份 locale + 常量表），测试锚点不变（锚点测函数名不测键名）；
- rust-i18n 的 `t!` 调用点需全量 grep 同步。

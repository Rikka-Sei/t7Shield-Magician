# 权限修复前置不满足时无用户可见反馈 — Issue

**状态:** open
**发现日期:** 2026-09-22
**来源:** T10 真机验证实测
**关联章节:** §4.13、§5
**关联决策 ID:** D33

## 1. 现象

用户点击「修复设备权限」按钮，若 `permission_fix_commands` 返回 None（无法确定当前用户 / setfacl 不可用 / 节点为空），代码路径正确走 FixPermissionsFailed → Issue → 胶囊保持，但**用户看不到任何变化**——按钮像没响应一样。spec §5 的「前置不满足→向导呈现手动指引」在 Issue 态的问题列表文案里，但列表内容不变（仍是权限不足条目），用户无法区分「点了没反应」和「点了但失败」。

## 2. 证据

- 真机复现：以 `env -i` 启动（无 USER/LOGNAME），点修复按钮无任何可见反应（polkit 不弹、胶囊不变、问题列表不变）。
- 代码：`environment_flow.rs` spawn_permission_fix 的 None 分支只调 `apply_environment_event(FixPermissionsFailed)`，无 Toast/结果区文案。

## 3. 拟议方向

前置不满足时向导内追加一条临时提示行（或 Toast）：「无法自动修复：<原因>，请按下方手动指引操作」；或结果区呈现一条中性文案。原因枚举：用户名不可确定 / setfacl 不可用 / 无待修复节点。

## 4. 状态

open——非阻塞（正常桌面会话 USER 恒存在），下一批 UI 打磨处理。

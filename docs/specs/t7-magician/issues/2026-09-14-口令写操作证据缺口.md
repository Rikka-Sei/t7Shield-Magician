# 口令写操作（设置/修改/删除）字节级证据缺口 — Issue

**状态:** open
**发现日期:** 2026-09-14
**最后更新:** 2026-09-14
**来源:** 代码审计（外部协议笔记与反汇编证据复核）
**关联章节:** §1.3（Out of Scope）、§4（`REQ-011 口令设置 / 修改 / 删除`）、§5（`ProtocolError::PasswordOperationUnspecified`）
**关联决策 ID:** D14

## 1. 现象

本规格无法为「设置口令 / 修改口令 / 删除口令」写出可执行的令牌流：权威笔记只给出这些能力**存在**的证据，没有给出 A 路上**逐字节**的调用序列。

- 有证据的部分：官方 A 路实现 `SIL_UsbNVMeWithTCG` 的虚表槽位 `+0x40 = SetPassword`（@0x39344）、`+0x48 = DeletePassword`（@0x3c120）；上层 `PSSDMgr` 公开 `Unlock / ValidatePassword / SetPassword / ChangePassword`。
- 没有证据的部分：这两个方法的 StartSession / SetTable / 事务序列、目标对象 UID、列号与取值，均未逐条反汇编。
- 属于另一条链路、因而**不可搬用**的部分：B 路（`SIL_PortableWithTBMac`）的 `SetPassword`（SPSP `0x00`）、`DeletePassword` / `ChangePassword` / `SetMasterUserName`（SPSP `0x02`）帧，走的是 0xFD 私有通道 + RSA-2048/OAEP-SHA256 载荷；本设备对 0xFD 的全部 SPSP 实测回 sense `03/11/00`，该通道不存在。

## 2. 证据链

| 证据 | 位置 |
|---|---|
| A 路虚表槽位 `+0x40 SetPassword` / `+0x48 DeletePassword`（仅符号与槽位，无字节序列） | t7Shield-protocol `analysis/protocol-notes.md` §1.1 |
| 对照：`Unlock` / `ValidatePassword` 有完整令牌流（因此本规格只对这两者写契约） | 同文件 §2、§2.2、§12.2、§12.5 |
| B 路 SPSP 表：`0x00` = SetPassword @0xb2b0、`0x02` = DeletePassword @0xbbac / ChangePassword @0xc578 | 同文件 §11.3 |
| 0xFD 通道在本设备不存在：全部 SPSP 回 sense `03/11/00`，协议表 `{0x00,0x01,0x02}` | 同文件 §0.1、§7.1；`analysis/probe-usb.md` §6 |
| 笔记自述待补项：`DeletePassword/ChangePassword/SetMasterUserName`（SPSP 0x02）帧内密文偏移未逐条反汇编 | 同文件 §11.10 |
| A 路桩函数先例（说明「有符号」不等于「有实现」）：`GetRandomKey` / `FactoryReset` = `mov w0,#2; ret` | 同文件 §0.3、§7.1 |

## 3. 根因

证据缺口，不是能力缺失：这三条能力在官方客户端里存在，但当前只有符号级与调用点级证据。按本规格的根植要求（不得凭空定义代码事实），任何写法都会变成臆造，因此 `REQ-011` 只定义到「返回明确错误」为止。

## 4. 影响

- 用户无法在客户端内设置/修改/删除口令；UI 必须把这三个入口呈现为受约束的不可用入口，并给出说明。
- 不影响解锁与口令校验两条主链路的可实施性。
- 若后续证据补齐，`REQ-011` 需要整体重写（新增决策 ID、替换契约、增加测试锚点与屏障），而不是在现有条款上打补丁。

## 5. 建议

闭环所需的证据（按性价比排序，需要用户决定是否投入）：

1. **反汇编补齐**：对 `SIL_UsbNVMeWithTCG::SetPassword`（@0x39344）与 `DeletePassword`（@0x3c120）做与 `Unlock` 相同粒度的 `pdf` 提取，落出调用序列（`ScopedSession::Begin` 的 eUID 对、`SetTable` 的目标 UID / 列号 / 取值、是否有事务）。
2. **Linux VM 实测**：按 §12.5 的 `sg_raw` 风格，在可回滚的盘上对候选序列做闭环（先做只读的 `GetTable` 侧写以确认对象语义，再做写入）。
3. **UI 层临时方案（不依赖新证据）**：把三个入口做成不可用并附本文档指针，与当前 spec 一致。

## 6. 闭环记录

- open：等待上述证据补齐，或等待用户决定把该能力永久移出范围（那样应把 D14 改为范围排除并同步 §1.3）。

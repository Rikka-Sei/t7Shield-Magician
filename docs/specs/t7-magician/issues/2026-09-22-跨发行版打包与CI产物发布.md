## 1. 目标

| 平台 | 方案 |
|---|---|
| NixOS / Nix 用户 | `nix run .` / `nix build .#magi`（flake 闭包封装，已有） |
| Ubuntu / Debian / 其他 | `nix build` 产出静态/便携二进制包，经 GitHub Actions CI 构建；发布 tag 时自动追加产物到 Release |

## 2. 拟议路径

### 2.1 Nix 侧（已有，验证即可）

- `nix run .` 已在 flake.nix 中定义 `packages.magi` / `apps.magi`；
- 补充：CI 中跑 `nix build .#magi` 验证 flake 求值与闭包完整性。

### 2.2 跨发行版便携包

两条候选路线（选一或并行）：

| 路线 | 做法 | 优劣 |
|---|---|---|
| A. nix-bundle / nix-portable | `nix build` → 打包整个闭包为自解压 tarball 或 AppImage | 体积大（含 GTK 运行时），零依赖目标机 |
| B. 静态链接（musl） | `nix build` 用 pkgsMusl 交叉编译，产出单二进制 | 体积小，GTK4 静态链接在 musl 下不成熟，风险高 |

建议先走 A（nix-bundle），成熟后探索 B。

### 2.3 GitHub Actions CI

```yaml
# .github/workflows/release.yml（拟议）
name: release
on:
  push:
    tags: ['v*']
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: DeterminateSystems/nix-installer-action@main
      - run: nix build .#magi
      - run: nix run .#magi-bundle   # 或 nix-bundle 产 AppImage
      - uses: softprops/action-gh-release@v2
        with:
          files: result/*
```

同时建议 `ci.yml`（每次 push 跑 `cargo test --workspace` + spec 三件套）。
